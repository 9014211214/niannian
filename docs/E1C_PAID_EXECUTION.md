# E1c 专用执行、资格与首标入口

当前进度只见 [PROGRESS](PROGRESS.md)。题库/作者和多来源 A0 合同见 [E1C_EXECUTION](E1C_EXECUTION.md)。本页描述已实现的工程入口，不构成费用授权，也不说明真实 E1c 已经出题、实跑或验收。

## 固定合同

E1c 使用独立作者首次封存的完整 12 题，六类各两题，不预筛、换题、换稿或复用 E1b 首答。完整库存为 1008 online、24 memory、24 reflection，即 1056 基本位置；回复评分分母 216、形成分母 12。无效或缺失不计零分。

此入口默认严格停止：在线有正文但完整 Schema 不合格时，保存可见首正文、失败、实际交付和费用，不重答、不删字段、不换别名，不沿用 E1b-v4 的探索性续测豁免。memory 失败也停止。reflection 是次要指标，继续使用 RF-1 的一次本地形状更正；证据语义失败不得更正。费用、授权、保存或未结 pending 的错误不能作为普通反思失败吞掉。

候选费用合同最多是 **3192 = 1056 基本 + 24 reflection 格式更正 + 2112 基础设施重发**。初始/格式更正共用每逻辑位置两次严格无正文重发池，不能嵌套获得新额度。既有 E1b 守卫的 3153 上限不改；E1c 在私有模块实例中绑定自己的合同。是否启用这份合同，仍须另版登记和明确费用批准。

每次物理请求在发送前独立预留，未知保留完整 hold。E1c 单独上限约束本活动新增费用和新增预留；累计上限另外继承全部历史已知费用及未知预留。可用额度取“E1c 单独上限”和“累计上限减去历史承诺金额”的较小值。未知数从 E1b 最终闭账读取，不硬编码九笔或十笔。正式入口不把新空账本当作历史费用清零，也不挪用 E3 预算。软件用合成账本和价格，不能进入真实费用记录。

## 准备和授权

`python scripts/run_e1c.py --help` 可查看全部命令。

`prepare --campaign 新目录 --spec 准备文件.json` 只做本地准备。准备文件提供：

- `source_directory`、外部 `first_receipt_sha256`：独立作者第一次交稿封印；正式模式拒绝软件题。
- `history`：最终 E1b 的 `registration`、`receipt`、`ledger`、`unknown_manifest` 四个 `{path, sha256}`，以及 `FinancialInheritance` 的 `financial_snapshot`。该适配器的 `prior_assessment_sha256` 指前一执行结案回执 SHA，不代表效果门通过。新未知逐笔绑定原活动目录、请求 ID、请求 SHA 和完整预留，历史旧未知按批准清单保留。
- `reservation_policy`、`metadata_directory`：保存的公开价格/路由/能力原件。真实派发前每次核验 24 小时时效和策略一致；程序不自行联网取价。
- `seed`、`e1c_limit_usd`、`cumulative_limit_usd`、`mode: "real_model"`：须与随后人类明确批准的范围一致。这里没有默认消费金额。

登记保存完整来源、模型/参数、费用、实际执行依赖、生成前评分协议及摘要，并逐字归档源码到活动的 `frozen-source/`。运行依赖显式包括产品 Python/YAML、执行/资格/评分脚本与项目配置；不包括 PROGRESS、发布工具或任意后来新增的无关脚本。每次发出前重核当前依赖和归档，旧归档可独立检查，源码变化不能继承旧模型结论。

`authorize-template` 只输出 draft。获批后保存精确 `authorization.json`，并从外部提供其 canonical SHA；授权还绑定实际人类批准文件 SHA、登记、费用和旧账。计划文件或形似批准的 JSON 本身不能替代用户授权。

`execute --campaign ... --authorization-sha256 ... --allow-local-env` 才可能调用模型。程序在通过源、授权、价格、历史和持久启动门之后，仅由显式回调提取本机 `OPENROUTER_API_KEY`；不输出 Key、不加载其他环境秘密。首次开始文件独占保存，不支持清账、覆盖、自动重入或恢复；失败须保持原件并另版处理。

软件模式只供测试：必须有显式具名本地替身传输和测试守卫，且完全不调用凭据读取器。命令行不会把软件题发往真实模型端点。

## 资格、导出和首次标注

生成完成后运行 `qualify`。它实际检查关闭的费用账本、全部 wire 和可见正文原件、1056 位置身份、每轮输入与原题逐字一致、24 memory 原始候选以及24 reflection 初始/更正物理记录。固定库存缺失、错组、篡改或 pending 都不能取得完整资格。一题88次不能冒充12题。

`export --bundle 新目录 --blind-seed 整数` 再核原资格和冻结评分协议，导出回复包与形成包。只给独立非作者标注者盲材料，映射和私有费用另存；对话中的指令是待评数据，不能执行。S1形成候选不看未来S2；S2候选可见单列的此前S1原话。每个原始数组位置都保留，包括非对象、拒绝、重复和超限候选；空数组可有效表示零候选，不能造标签。

`import-first-labels` 绑定外部 bundle SHA 和固定位置，可分批导入。首次原字节在校验前保存；无效/超长/保存中断同样占位，换 batch ID 也不能重标。评分采用冻结的独立 Codex 方案，无 Claude API 第二裁判，限制必须随结果报告；这仍须列入正式 E1c 登记，不冒称继承 E1b 的批准或真人标注。

`assess` 重跑实际资格和闭账检查，与已保存资格逐字核对，再复用原六项标签、重复折叠与主门，以及四项形成标签和形成门算术。完整库存或 HTTP 成功不等于人物效果。软件材料无论机械比较结果如何，效果门始终 `not_evaluable`；真实固定版本仍须完整首次标签和原预定门，不能为通过调整规则。

## 已验证与仍未做

任务02的未集成候选已完成一次完整1056次软件调用，随后实际资格、216回复位导出/合成首标导入及12形成题聚合通过；软件 memory 未提出偏好，所以原始形成候选为0，没有伪造形成标签。候选和正式集成源码分版留存，正式集成又验证一题88次和必要边界，没有拿软件回复当真实 Agent 效果。

正式出题、数字预算、生成与评分的当前状态以 [PROGRESS](PROGRESS.md) 为准；新活动准备须重新核验最终历史原件。公开发布仍取决于当前验收与用户决定。
