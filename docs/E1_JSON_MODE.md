## 已知事实与未恢复的信息

T7.4允许auto却只收工具，导致第12项正文JSON被拒。T7.5接收两种真实载体，实跑29项通过，第30项在旧传输清洗器报invalid_choices；该次HTTP200费用0.00015456美元仍保留。供应商日志已匹配精确generation ID和tool_calls结束类型，但未开启I/O日志，具体工具内容不可恢复。不能把该错误总码写成已经确定的某个工具字段错误；不会为恢复内容打开新的供应商内容日志。

原消息末尾仍有客户端指定native唯一通道系统指令。因此auto和双载体不是一致的发送约束。本版用原有纯函数绑定器，将这唯一格式系统指令改为plain_json；每个实际wire均核除了这条格式指令，题目、人物、策略、用户原话与其余系统消息不变。

## 显式模式与严格接收

[Qwen3.7 Flash官方说明](https://openrouter.ai/qwen/qwen3.7-flash)明确支持JSON输出而不支持JSON Schema强制；[参数文档](https://openrouter.ai/docs/api/reference/parameters)区分json_object和json_schema。实际请求移除tools/tool_choice，新增response_format={type:json_object}；模型、only Alibaba、禁止fallback、require_parameters、data_collection=deny、关闭reasoning及原温度/输出限额不变。

原aria_turn_decision参数schema保留在本地trial。正文必须是唯一完整JSON对象、没有工具调用，并按原schema和生产决策/交付护栏检验。JSON模式不保证字段和策略正确；必填、类型、枚举、范围、额外字段、隐藏推理、重复键、截断及usage仍严格拒收。不补缺字段、不改答案、不把普通回复包装成工具结果。

传输在同一次HTTP响应中额外保存固定枚举的形状诊断：选择类型/数量、角色/结束类型、内容类型、工具数量及参数格式等，不保存任意诊断原文、隐藏推理或凭据。真实对象arguments或明确空工具载体的正规化须另记实际类型；本版正文通道仍禁止真实工具。不因新增诊断而给第30项追补未知形状。
