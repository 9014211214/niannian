# C-test 第二版：补齐必填观察字段

进度入口：[PROGRESS](PROGRESS.md)。原协议：[CTEST_EXECUTION](CTEST_EXECUTION.md)。本修订登记在新的真实请求之前。

第一版实际发送 40 次，39 次会后处理有效；第 40 次返回了事实 JSON，却缺少 `cognitive_observations`。执行器拒绝把缺失字段当作零观察并停发。其余 56 次未发送，整版不可评。已知费用 0.400796 美元，无新增未知费用。102 份冻结源原字节、登记、请求账本、返回正文及失败回执全部保留于本机任务原件，不覆盖、不续跑。

根因是 C1 启用时仍展示三字段主 JSON 示例，再用后缀要求另加观察字段。新版本只在 C1 启用时把第四个必填数组放进同一个主示例，并在生产抽取器中检查完整结构；缺字段不能推进校准或写成空观察。C1 关闭时原提示字节保持不变。

第二版重新测完整 **12 人、96 会话、96 memory 调用**。脚本、虚构时钟、六变化/六对照分组、至少4/6变化触发且0/6对照误触发的判据均不变；不复用前版39次，不挑选两版较好回复。在线、reflection和裁判调用仍为零。结论仍只针对虚构脚本上的会后组件，不代表医学有效性或真实在线回复质量。

沿用用户批准的 C-test 2 美元总额及累计已知2美元停报约定。带入 E1 已知0.026719172及首版C-test 0.400796后，本次新额度为 **1.572484828 美元**。两笔历史未知原样保留；新错误或费用不明立即停发。两版费用合并报告，不将新目录视为新消费授权。

`scripts/run_ctest_repair.py` 在发送前重新计算首版登记封印，逐条对照只读 SQLite 账本与费用回执，核对39次完成、40次请求、56次未发及第40次缺字段原件；复查全部102份旧冻结源、未改的原入口及协议、未改脚本、当前源码、公开参数与价格。旧登记或账本不一致、仍有待处理数据库日志时拒绝发送。第二版保留完整独立分母，不继承首版或修复前安装检查的通过结论。

第二版使用项目内固定 `ctest-repair-v2-authorization.started.json`，复制登记、重新冻结或更换输出目录不能重置授权。准备和核对均不读取密钥；只有明确 `--execute --allow-local-env` 才提取本机 `OPENROUTER_API_KEY`，不导入其他变量。启动记录不自动清除；发送前失败需由执行负责人核对零发送证据后处理。两个脚本均不自动修复、重试或寻找更好结果；这是已知失败、明确修正后的新版本前瞻测量。
