# 设计缺陷审计（20261006-03）

起因：R1 的准入规则把真实候选全部拒收（E1b-R 14→0，E1c 5→0），功能从来没有生效过。
用户要求排查有没有同类的严重缺陷。

**本次检查范围**：只读代码和已有实跑原件；对规则做了离线探针（直接调用产品函数，不调用模型）。
0 次模型调用，未改代码。下文的“探针”都是我临时写的说法，不是正式测试集，只用来说明问题确实存在。

## 共同根因

有四处是同一类问题：**用固定词表或正则表达式，判断本该交给模型理解的语义**；
验证用的题又是知道规则的人写的，所以测试通过不代表换一种说法也能用。
另一处的问题是：**把实验的“失败即停”纪律原样搬进了产品**。

我的责任：
- R1 设计写了“代码校验”，但没有明确规定“代码不判断语义”；
- 我没有检查实现后的功能在真实运行中是否真的生效；
- 实验设计里一直没有“曝光率”这一类指标，直到 20261006-02 才补上。

## 缺陷清单

### 致命：功能从未生效，或产品在真实使用中会失效

| # | 缺陷 | 证据 | 影响 |
| --- | --- | --- | --- |
| D1 | **R1 准入用正则白名单**判断“是不是相处要求” | 真实候选 19 条，接受 0 条 | 老人说的相处方式永远记不住。修复方案 R1-A 已获批 |
| D2 | **C1 变化提醒用 9 个关键词预筛**（`_COGNITIVE_HINT`：忘、记不住、想不起、叫啥……）。没命中关键词的话，模型根本看不到 | 8 个自然说法探针命中 0 个，例如“钥匙又找不着了”“刚说的事一转头就没印象了”“今天礼拜几来着？日子过糊涂了”。C-test 的“变化组”脚本恰好用了这些关键词（480 句中 42 句命中） | C-test 的 5/6 通过**不能说明真实可用**。同一个词表还负责把认知健康内容排除出普通记忆和人物分析，漏掉的说法会进入普通记忆，**隐私边界也跟着失守** |
| D3 | **产品调用保护“一次失败，永久停止”**。在线 JSON 不合格、memory 失败、一次 429 或一笔费用未知，都会把“已停止”写进本地台账，此后所有模型调用都停，台账不能重置 | 代码 `minimal_calls._snapshot` 中，任何 failed 记录都会触发 `request_failed`；`minimal.py` 失败后执行 `_halt_models()`。真实格式失败率：E1b-R 238 次 JSON 中失败 3 次，E1c 45 次中失败 1 次，约 1～2% | 按每轮 1.5% 估算，一次 50 轮的聊天约有一半概率中途变成只会说兜底话的“哑巴”，而且之后一直如此。这是实验纪律误用到了产品上 |
| D4 | **推断的人物假设从未达到可用状态** | E1b-R 和 E1c 共 121 份档案快照、74 条假设，**全部是 candidate，0 条 working**；在线请求中人物假设块的注入为 0 | 产品的另一根支柱“理解他是什么样的人”从来没有影响过任何一句回复，reflection 的价值没有得到过任何验证。门槛偏保守是有意的设计（不为演示降门槛），但目前**没有任何证据表明它在现实的会话数内能生效** |

### 严重：安全

| # | 缺陷 | 证据 | 影响 |
| --- | --- | --- | --- |
| D5 | **急症和心理风险的确定性分流只靠关键词** | 探针：“左边胳膊麻了，说话也不利索”（中风征兆）、“摔了一跤，起不来了”“我把这几个月的安眠药都攒着呢”“活够了，早点走了也好”“我想去陪老伴了”都**没有触发**；只有“我不想活了”“胸口闷得厉害，喘不上气”这类字面说法触发 | 在线模型的提示里有安全规则，回复本身可能仍然得体，但确定性的急症流程（120 提示、护理升级）不会启动。这对老人产品是安全缺口 |

### 中等：产品流程

| # | 缺陷 | 影响 |
| --- | --- | --- |
| D6 | **会后整理要有人手动点“整理”**；关闭或闲置只封存，不整理 | 真实使用中如果没人点，产品就什么都学不到：事实、相处说明、变化提醒全部停在原地。这是当初为控制费用做的决定，需要重新权衡 |

### 检查后未发现问题的部分

- **事实记忆能进入在线回复**：已提取的事实中 1183 条可引用、362 条不可引用；E1b-R 抽查 222 个在线请求，其中 43 个带有事实记忆块。
- **在线 JSON 格式**：E1b-R 238 次中 235 次通过。问题出在失败之后怎么处理（D3），而不是格式本身。
- EM-1、C1、R1 的定向测试此前抽查 193 项通过。这只说明软件按规则运行，不能说明规则覆盖了真实说法。

## 修复方案（均为 0 费用的工程工作；付费复测另行批准）

| 卡 | 修复 | 验收 |
| --- | --- | --- |
| **R1-A**（已批准） | 见 [VALIDATION](VALIDATION.md)：只校验原话逐字出处，并拒绝危险类别；安全门回到本人确认 | 安全负例 30/30 仍拒收；19 条真实候选离线重放后，有依据的能进入 proposed |
| **G-A 调用保护分层** | ① 预算类（费用未知、达到限额）保持“下次请求前停止”。② 输出不合格：当轮用兜底回复，然后继续，不停整个产品。③ 没收到内容的错误（429、5xx）：每次最多重发 2 次。④ 连续 3 轮失败才暂停，界面明确提示，并提供本人或管理员可操作的“恢复”。⑤ 台账只追加、不删除，恢复操作也记入台账 | 替身测试：单次格式失败后下一轮正常调用；连续 3 次失败后暂停；恢复后继续；预算停止不受影响 |
| **C1-A 去掉关键词预筛** | 本人开启 C1 后，memory 在同一次调用中审阅全部本人轮次，提出变化观察（原话由代码逐字校验）。认知健康内容的隐私排除改为“模型标注 + 关键词兜底”，标注出的轮次从普通记忆和人物分析中移除 | 由**不看代码的独立作者**写自然说法的正例和反例做离线检查；C-test v3 改用独立作者写的脚本（付费，另批，约 1.4 美元） |
| **S-A 模型参与风险标注** | 在线 JSON 新增 `safety_concern` 字段（none / self_harm / medical_emergency / fall / unsafe_medication），由同一次调用给出，不增加调用；非 none 时进入现有的确定性处理流程。关键词仍保留，作为底线 | 由独立作者写 40 条自然说法（正例、反例各半）；关键词底线原有测试全部保持；付费小测另批 |
| **H-diag 人物假设诊断** | 用已有的 74 条 candidate 的证据记录离线重放状态规则，逐条列出卡在哪个门：支持会话数、轮次数、置信度、事件独立性 | 交诊断表给我，再由用户决定是否调整门槛。**不先降门槛** |
| **P-1 流程纪律** | 以后任何规则型的门：① 测试题由不看代码的独立作者写；② 每个实验都报告“功能实际生效的比例”（曝光率），低于 80% 判为“不可评”，而不是“通过”或“失败” | 写入 AGENTS 或 VALIDATION 的共同纪律 |

需要用户决定的产品问题：
- D6：会后整理是否改为会话结束后自动进行，按日设费用上限，并在界面上提供开关；
- D7：在线对话中是否加一句复述确认。

两项都会改变产品行为，建议在 E1c-v2 之后再定，以免给实验增加变量。

## 顺序

1. **并行（执行 agent，0 费用）**：R1-A、G-A、C1-A、S-A、H-diag。
2. R1-A 离线重放通过，且 G-A 合入后，冻结并运行 E1c-v2（已批准）。G-A 必须在冻结前合入，这样 E1c-v2 测的就是修复后的产品。

4. H-diag 结果出来后，与用户一起决定人物假设门槛。
5. 首发仍等 E1c-v2 的效果结论；首发说明中如实写明 D4、D5 的现状。
