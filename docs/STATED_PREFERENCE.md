# R1 协议与实现：本人确认的相处说明（stated_preference）

本文保留 20260930-05 的设计依据，当前实现按 R1 协议 **2.0** 说明（20261007-03 修订）。
模型在同次 memory 提取中提交语义审核声明，代码校验出处、声明形状和状态，再由本人确认；
这些环节都不能独立保证模型的语义判断正确。任务状态、测试结果、
浏览器验收和未完成项只维护在 [PROGRESS](PROGRESS.md)，本页不另立进度表。

## 1. 要解决的缺口

产品三件事的第一件是“本人能确认和纠正的相处说明”（见 [PRODUCT](PRODUCT.md)）。设计前的缺口：

- 会后 reflection 已能把本人明说的偏好标为 `evidence_basis=stated_preference`，但它仍
  作为**推断型人物假设**进入同一条流水线，要满足“≥2 个支持会话、≥3 条支持轮次、
  置信 ≥0.5”才升为 working，才进入在线提示（`diagnosis.py` 状态规则、
  `prompt.confirmed_prompt_hypotheses`）。
- 结果：老人在第 2 次会话明确说“安排日子以前先问问我”，第 3 次会话在线模型**看不到**。
  这正是 E1 陷阱题要测的场景；E1 的 B1 臂靠作者夹具补上，产品本身没有。
- 本人明说的话和系统推断混放，也无法“撤回”——只能等反证把置信压低。

目标：本人明说并确认过的相处方式，**下一次会话起就生效**；不靠置信累计；本人可以撤回；
和推断假设分开保存、分开显示；绝不因此获得任何分享或通知权限。

## 2. 设计原则

1. **来源是本人原话，不是模型判断。** 每条说明必须带逐字原话出处，代码校验，校验不过就不存。
2. **确认是独立的本人操作。** 当前通过页面明确确认；模型不能自行确认，在线对话确认仍属 D7 待定范围。
   新模型条目还必须通过协议 2.0 的准入；仅有历史确认记录不能替代当前审核。
3. **当下意愿优先。** 本轮本人新的明确说法压过记录；记录的说明压过推断假设。
4. **不是权限。** 分享、转达、通知只由护理/授权表单决定；像授权的内容不能存成相处说明。
5. **与 E1 区分且可对照。** 在线注入沿用 E1 B1 的说明字段形状，但来源、标题和优先级提示
   必须反映真实产品。字段相同不代表提示词相同，也不把旧 E1 效果结论迁移为新版产品结论。
6. **不在线加码。** 不改在线 v1 工具 schema，不增加在线输出 token；提取放在会后 memory 步骤。

## 3. 数据形状

`PersonaProfile` 新增 `stated_preferences: List[StatedPreference]`（默认空，旧档案自动兼容）。

| 字段 | 说明 |
| --- | --- |
| `id` | `pref_` 前缀，满足现有 `_BASIS_ID` 规则，可被 v2 引用 |
| `do` | 做法，≤60 字，例如忠实转述为“聊天时等我把话讲完再回应”；仍需满足当前语义声明与出处边界 |
| `scope` | 从完整本人原话机械回填，≤60 字；如“聊天时先等我把话讲完再回应”，不由模型追加医疗或授权条件 |
| `not_implies` | 存储上限 3 条；当前代码固定为“不代表所有场景都适用”“不代表同意执行任何现实动作” |
| `quotes` | 1～2 条 `{session_id, turn_index, text}`，逐字本人原话 |
| `confirmation` | `{session_id, turn_index, text}` 或 `{source:"ui", at}`；待确认时为空 |
| `status` | `proposed` / `confirmed` / `declined` / `withdrawn` / `superseded` |
| `supersedes` | 取代的旧说明 id，可空 |
| `history` | 状态变化记录 `{at, from, to, source, quote?}`，只增不改 |
| `created_at` / `updated_at` | ISO 时间 |
| `extraction_source` | `rule` / `model`，区分本地规则提议与会后模型提议 |
| `semantic_review` | 新模型提议必填的同次语义声明；旧记录和本地规则示意可为 null，但不能因此进入真实使用 |

实现中的历史记录同时支持读取 `from` 和 `from_status`；默认档案序列化使用
`from_status`，界面兼容两种键。确认和撤回来源仍在历史中单独记录，不覆盖提取来源。

不含置信、框架标签、目标分数。DISC/Big Five 等词不得出现在 `do`、`scope` 中。

`semantic_review` 是严格对象，不允许多余或缺失字段。`version` 固定为
`preference_semantics_v1`；`kind` 只允许 `communication_style`、`permission_boundary`、
`action_request`、`fact`、`person_inference`、`unclear`。另有四项严格布尔值，不能用数字或字符串代替：

| 字段 | 模型应审核的含义 |
| --- | --- |
| `owner_requested` | 本人当前确实提出要求，不是转述、举例、否认或撤回；否定句提出的有效要求不等于否认该要求 |
| `quote_supported` | `do` 得到所引本人原话支持 |
| `scope_preserved` | 条件、对象、时限完整保留 |
| `no_permission_claim` | `do` 和 `scope` 不含授予、限制或推断现实行动/披露权限 |

只有 `kind=communication_style` 且四项均为 true 才满足模型语义声明门。它来自**同一次模型输出**，
没有新增独立分类模型或第二次审核调用；声明可能有错，代码核到的 true 不是独立正确性证明。

**状态转换（其余一律拒绝）：**

```
proposed ──本人确认──▶ confirmed ──本人撤回──▶ withdrawn
    │                      └──新说明被确认──▶ superseded
    └──本人说不记──▶ declined
```

撤回、取代后保留原话和历史，用于追溯，但永不进入在线提示。整条删除走现有“忘掉本次”流程，
单条删除是后续工作。

## 4. 生命周期

**4.1 形成（会后 memory 步骤，不改在线协议）**

在 `consolidator.LLMExtractor` 现有的 facts/relationships 之外增加第三类行
`stated_preferences`。模型只能提议，代码负责判定：

1. `quotes` 必须能在已封存会话的本人轮次中逐字找到；说明提取使用独立严格匹配，
   不沿用事实抽取的标点归一化容错。找不到、原始轮次被隐私层排除或来源会话不符，
   就丢弃并记录原因。安全检查读取完整本人轮次，不能裁掉“不要”“女儿说”等上下文。
2. 提取结果**一律为 `proposed`**。模型提供的 `status`、`confirmation` 或引述的对话肯定
   都不能使它自动变成 `confirmed`；必须经过本人单独确认操作。旧档案已有的对话确认记录
   仍可读，但新提取不再走自动激活。在线复述确认属于 D7 待定范围。
3. 语义声明必须满足上节严格形状、类别和四项布尔门；否则拒绝进入本功能。
   现实行动或披露的权限边界，即使是限制性的“不要替我答应”，也不能伪装为交流方式。
   原话出处、完整范围和有限隐私/医疗/人格兜底另行校验；代码不凭声明保证语义忠实。
4. 取代：模型可给 `supersedes` 指向已有 confirmed id；只有新说明本身被确认时，旧说明
   才转为 superseded。
5. 占位模式（默认不调模型）：少量规则识别“先问我”“别替我定”、一次一步、放慢节奏
   等原话，标注来源为规则。最小页面要先封存，再明确点击“本地规则提取相处说明”；
   此操作只提取说明，不完成事实抽取、人物反思或原会后任务。提议生成后由本人
   点击“按这句话记下”，只在 `local_preview` 验证流程。这类 `rule` 记录即使已确认，
   也不进入真实在线提示、引用依据或 reflection 历史；不能把规则流程说成模型学会了理解人。

**4.2 确认与撤回（本人操作）**

- 理解面板新增“他说过希望怎样被对待”一栏，与“事实”“人物假设”分开。
- 待确认条目显示原话和“按这句话记下 / 不记”；已确认条目显示“撤回”。
- 新接口 `POST /api/minimal/preference`，`{action: confirm|decline|withdraw, id}`，
  在用户锁内修改并持久化，写 `history`；回放模式只读，按钮禁用。
- 撤回保存成功后的下一轮构建提示不再包含该条；不能撤销已经发出的请求。
- 护理页首发不显示相处说明（属于老人本人的沟通偏好，不是护理数据）。
- 缺少合格 `semantic_review` 的旧模型记录保留原状态、原话和操作历史，界面标为需要重新审核。
  待确认旧条目不能再次点击确认，已确认旧条目也不进入真实使用；拒绝或撤回仍可操作。
  本人需在**新会话重新表达并明确启动会后整理**，形成符合当前协议的新提议后再确认；
  不自动回填审核字段、不重跑旧会话，也不把历史确认当作语义审核完成。

**4.3 在线使用**

- 真实使用只选 `confirmed` 且通过当前模型准入的条目，最多 4 条（与 E1 夹具上限一致），
  按确认时间取最新。统一资格函数同时约束在线提示、引用依据、reflection 和 memory 的历史说明输入。
- 生产注入使用 `_untrusted_block("本人确认的相处说明", "stated_preference_confirmed", [...])`，
  字段 `id / do / scope / not_implies / quotes / confirmation / admission / extraction_source`，原话写成
  `session=…,turn=…: 原话`；页面确认则为 `{source:"ui",at}`。位置在基础提示各块之后、
  在线决策约定之前。原 E1 标题含“作者合成夹具，非本次学习结果”，来源键为
  `e1_author_supplied_stated_fixture`，不能把它与生产来源混同。
- 块首固定两句：“本人当下新的明确说法优先于这些记录”“与推断的人物假设冲突时以本人确认的为准”。
- v2的可引用依据列表加入这些id，claim写 `本人确认的相处说明：` + `do`，不再伪造成人物假设。
  当前最小入口v3通过上述通用已确认说明块接收id/do等字段，没有增加v2的deliberation或applied_basis字段。
- 没有已确认说明时不增加本功能的提示块。这只说明同一协议下的R1差量，不能据此称
  当前v3提示与旧E1的v1基线逐字相同；v3另有同次安全标注合同。
- R1本身不改旧v1决策Schema；增加说明会增加输入长度，当前新版的真实延迟尚不能
  由旧实验推算成已测结果。

**4.4 会后 reflection**

reflection 只接收通过当前准入且已确认的说明，作为只读历史块；旧待审核记录和规则示意不进入该块。
不得仅凭历史说明再次累计证据或置信，不能作相反泛化；本次原话出现直接反证时仍须记录范围和冲突，
不得替本人撤回说明。reflection 另有自己的 2.4 提示合同和 2.0 数据协议，不与 R1 协议混为一谈。

## 5. 与 E1 的关系和实现时机

- E1 B1 测的是作者预置说明下的模型回复。R1 沿用其 `id/do/scope/not_implies/quotes/confirmation`
  字段形状，方便后续另版对照，但生产来源、优先级提示和调用实现已有差异。
  原 E1 不证明本版提取、确认、人物学习或实际使用效果；本地单元测试和占位浏览器流程也只验证
  软件边界，不代替真实模型效果检查。
- 本设计也不要求在线模型主动复述确认。是否在提示里加“本人明确提出相处方式时，一句话复述并问是否这样记”
  留作 R1 之后的产品调整，届时要单独说明它未经 E1 检验。
- `persona.py`、`prompt.py`、`consolidator.py`、`minimal.py`、`minimal.html`、`online_decision.py`
  曾属于 T6 冻结清单。旧实验必须用保存的旧源码快照复验；产品修订不能重封旧实验、覆盖原失败，
  或继承旧软件快照与真实模型结果。当前快照位置及记录见 [PROGRESS](PROGRESS.md)。

## 6. 验收（全部本地，0 费用）

1. 模型与状态：非法转换全部拒绝；旧档案（无该字段）正常加载保存。
2. 提取：出处不匹配、严格声明字段错误、类别不合格或任一布尔为 false 时拒收；有限安全兜底仍拒收命中的危险内容。
   这是机械合同验收，不能由预置 true/false 软件夹具推算语义识别正确率。
3. 跨会话：第 2 次会话提议通过当前准入并经本人确认，第 3 次会话第一轮提示中出现，来源明确为产品记录。
4. proposed / declined / withdrawn / superseded 不进入在线提示；缺审核旧记录和规则示意不进入真实使用；最多 4 条。
5. 撤回后下一轮即不再出现；回放不修改任何状态。
6. 同一代码和提示协议版本下，没有可用说明时不增加 R1 提示块；检查同版本的无说明差量，
   不要求与旧版本提示逐字相同，不回改旧快照结果。
7. v2 引用依据和 reflection 历史块只包含通过当前准入的已确认说明。
8. `local_preview` 能走通“说出 → 规则提议 → 本人确认 → 下次选择输入 → 撤回”；
   切到真实模式后规则记录不可用，不把占位回复当模型尊重了说明。
9. 全量测试通过。

## 8. 实现边界与 R8 输入记录

核心实现为 `aria/engine/memory/stated_preferences.py`；`PersonaProfile.stated_preferences`
独立持久化，`MemoryConsolidator` 和会后队列合并该字段，不修改人物假设的跨会话门槛。
`transition_preference` 只接受三种本人操作，先校验再修改；最小页面在用户锁内复制档案、
保存成功后替换活动档案。替代说明确认之前，仍符合当前准入的原说明保持有效；旧缺审核条目即使保持 confirmed 状态也不可用。目标已撤回等冲突不允许半途变更。
旧说明及操作历史保留，重复提取同一会话不会重新激活已撤回说明。

模型提取沿用 R1-A 的提议与确认分工，并以 R1 2.0 增加同次语义审核声明。当前模型路径如下：

- `quotes` 仍须是本次会话本人轮次的连续原话；会话、轮号、隐私排除和长度上限逐项校验。
  保存完整本人轮次，不能通过截句隐藏转述、否定、条件或分享边界。
- `do` 可以忠实转述，不再要求原话子串，也不要求出现指定请求句式、沟通动词或与原话共享
  词面片段。模型必须同时声明类别及四项判断；代码**不证明语义一致**，模型错误地声明全 true
  时仍可能产生不忠实的待确认项，本人需对照原话否决。本人确认也不是独立语义效果验收。
- 事实与偏好、转述与本人要求、否定式请求与否认/撤回的区分由模型按完整语境声明。
  `_FACT_ONLY`、否定句和转述词面门不再用于当前 model 来源准入；它们仍在本地规则示意解析器中。
  模型路径保留有限的隐私/接收对象、医疗规则和人格/因果词面兜底，`do` 另检查明确第三方动作目标，
  不声称覆盖所有危险表达。已有隐私接收对象规则仍会误拒“我一向习惯先把话讲完”；
  这是保留的已知限制，没有通过补白名单、扩词表或替换原失败记录宣称解决。
- 范围不能由模型任意扩大。短来源的完整正文直接回填 `scope`，使前后条件与限定一起保留；
  仅去掉句末标点和不含条件的“所以你记着：”等话语引导，完整 `quotes` 不改。
  多条来源按顺序合并。若完整范围超过既有 60 字存储上限，明确以
  `preference_full_scope_too_long` 拒收，不截断条件，不把长度不足说成语义无依据。
  逐字 `do` 和同义转述一视同仁，不提供逐字片段覆盖的特例。
- `not_implies` 仍由代码给固定边界，不采信模型补充的心理结论。提议不授予任何现实动作、
  分享或护理权限；人格理解和偏好不能改变医疗规则或升级阈值。
- 每个新条目只到 `proposed`，即便模型附有看似完整的对话确认也不自动生效。面板同时
  展示转述做法、完整原话和范围；通过当前准入且本人确认后才进入真实在线提示，拒绝与撤回只追加历史。
- 本地占位规则继续只提议已有的三个示例类型，来源标为 `rule`；它们不是模型准入的白名单，
  也不代表模型提取；确认与使用仅限 `local_preview`，真实在线、依据和 reflection 一律排除。
  暂停的旧 E3 加载器暂保留独立兼容用的 `_REQUEST` 符号，生产准入不使用。

在线当前将最多四条通过当前准入的已确认说明及其 `scope`、完整原话和禁止外推边界一起交给模型，由模型结合
当前说法判断适用性；**尚没有独立的机械语义匹配器按场景过滤这些已确认说明**。不能把“已进入
带范围的提示”说成“只在适用场景注入”，也不能把本地管线测试说成模型真的遵守了范围。提取、
确认、持久化、真实提示构建与撤回的软件测试可以独立验证；真实模型是否提出合格候选、最终

R8 在本轮提示实际构建时保存选择快照，不从后来变化的档案重建。事实记录的是经过提示清洗的
实际选入摘要；人物假设同时提供实际清洗、截断后的 `injected_text`；明确说明记录的是实际选入字段。
