# E1c-v2 执行与证据合同

当前状态只见 [PROGRESS](PROGRESS.md)。本文件解释独立版本的实现与操作，不授予费用、公开发布或额外恢复权限。设计依据是 [VALIDATION](VALIDATION.md) 的 E1c-v2 修订和 [DESIGN_AUDIT](DESIGN_AUDIT.md)。

## 固定范围

- 保留原独立作者的整份首次交稿及其 SHA；只由程序从原顺序剔除已曝光的 `e1c_a1`、`e1c_a2`，其余 10 题不预筛、不换题、不调提示。
- 10 题、180 个评分回复、10 个形成案例；840 在线、20 memory、20 reflection 基本位置。因产品安全接管或失败 memory 封存而未调用的位置保留原因，不伪造请求。
- 同一题的前两次会话共享。程序通过实际本人确认接口确认全部 proposed 条目，不按参考答案选择；这是明确披露的脚本确认，不是老人真实操作。
- A0 删除所有作者登记来源上的相处说明及相关事实、人物和关系记录；A1 保留。第三次会话每臂重复三次，各取第 8～10 轮评分。合成情绪和虚构人群的限制不变。

旧 E1c-v1 的执行器、停止规则、1056/216/12 分母、原答、费用和结论保持原样。新入口是 `scripts/run_e1c_v2.py`，新执行目录不得复用旧目录。

## 产品行为与预算

实际运行使用 minimal 的 v3 同轮安全语义协议、memory 隐私字段及 `ProductCallGuard`，没有单独的预筛或裁判 API。

- 在线格式失败交付产品实际固定兜底，并按实际回复评分；原首正文另外保存，不重新请求坏正文。
- 已结算的失败 memory 会话封存、跳过隐私判断未完成的 reflection；后续会话可继续。失败仍属于 10 个形成案例的分母。
- reflection 采用产品原有的最多一次格式更正，初始正文和更正正文分别保存，不冒称首次输出成功。
- 只有费用已知、确实没有模型内容的 429/5xx 可最多追加两次相同物理请求。费用未知、预算或保存不确定阻断下一次请求；每笔未知保留完整预留。
- 三次连续逻辑失败保留产品暂停状态。本执行器不模拟本人点击恢复，也不自动续跑；停止目录保留为原件。
- 2700 是物理调用库存上界（基本位置及 20 个最多一次的 reflection 更正各最多三次物理尝试），并非费用授权或必发次数。

费用从旧 E1c 闭账继承，使用 `min(E1c 总限额－旧 E1c 已知及未知预留, 累计总限额－历史累计已知及未知预留)`。当前批准的总限额为 E1c 1.5 美元、累计 4.5 美元，均含已花费用及未知预留；以最新进度为准。旧账本、回执、原登记和逐笔未知清单在每次发送前复核，不因新版本清零。

## 资格和判定

资格核对原始请求、可见首正文、产品持久轮次、形成捕获、reflection 各步骤、完整生成清单及实际共享账本。HTTP 成功不等于正文有效；真实生成与软件替身必须分开标记。形成捕获重用产品严格 JSON 解析，重复键、非有限数字或第二个 JSON 不被覆盖成合法候选。

形成归属用产品的稳定 ID、当前会话、原始 `do` 及全部引文来源核对。存储层扩展为完整本人原话时，合法子串仍能归属；错误会话、另一轮同文及重复候选不能抢占已接受条目。盲包去除内部会话 ID，保留原话、候选和评分所需上下文。

| 门 | 预先固定的规则 |
| --- | --- |
| 主门 | A1 在至少 4/10 题的多数违例数少于 A0，且没有更差题 |
| 形成门 | 至少 8/10 题有受原话支持、符合预期且实际进入 proposed 的说明；授权或人格误提取为 0 |
| 格式门 | 180 个评分回复中产品兜底不超过 9 个（5%） |
| 曝光门 | A1 S3 的 300 个预定位置中，至少 240 个实际请求包含本人确认说明；缺失位置不进分子，分母仍为 300 |

曝光不足时主门为不可评；形成、格式及安全/隐私发现仍分别报告，不用不可评遮蔽失败。人物假设阈值没有因本实验降低。候选 unsupported 数另报；不把提出说明或确认脚本当人格理解正确率。

每个评分位置只接受独立非作者的第一次标签提交。错误首标原件及其占用位置保留，不换批次 ID 重评。软件标签仅验证计算和收件，不取得真实模型效果资格。没有真人样本、真人校准或 Claude 第二裁判。

## 本地流程

先通过 R1-A 开发重放、G-A 集成及独立工程复核，再冻结完整源码。`prepare` 的 spec 包含原首稿目录及回执 SHA、旧 E1c 四项历史路径/SHA（registration、receipt、ledger、完整 unknown_manifest）、公开模型价格元数据目录、预留策略、固定种子、上述两个总限额和 `mode: real_model`。

```powershell
.venv\Scripts\python.exe -B -X utf8 scripts/run_e1c_v2.py prepare --campaign <新目录> --spec <登记参数.json>
.venv\Scripts\python.exe -B -X utf8 scripts/run_e1c_v2.py authorize-template --campaign <新目录>
.venv\Scripts\python.exe -B -X utf8 scripts/run_e1c_v2.py verify --campaign <新目录> --authorization-sha256 <批准文件的规范化SHA>
```

授权文件应由执行人根据已存在的用户批准及独审结果写入，绑定新登记、继承财务和批准原文文件。`prepare` 和 `verify` 不读取 Key，也不发送模型请求。

唯一实际派发由主代理执行：

```powershell
.venv\Scripts\python.exe -B -X utf8 scripts/run_e1c_v2.py execute --campaign <新目录> --authorization-sha256 <SHA> --allow-local-env
```

这才会在全部检查及独占开始标记后，通过既有阅读器仅提取 `.env` 中的 `OPENROUTER_API_KEY`。已有开始标记不能当作重新派发许可。预算、未知或连续失败暂停时先保留闭账，不改标记继续跑。

生成完整后运行 `qualify`；随后 `export --bundle <新盲包目录> --blind-seed <固定种子>`。独立裁判仅读取各 `blind/packet.json`，结果以 `import-first-labels` 提交原始文件、批次 ID 和明确的 `--expected-ids` 文件；`assess` 重核封存生成及首标后给出各门结果。全部后处理均不读取 Key或新增模型请求。

软件验证使用明确命名的本地传输替身并拒绝网络与 `.env`；完整冻结验收和仅部分执行源绑定的长链演练必须分别报告。软件目录不可通过 CLI 冒充正式实跑。
