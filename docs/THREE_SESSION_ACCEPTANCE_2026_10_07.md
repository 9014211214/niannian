## 固定范围与调用库存

同一虚构人物连续 3 次会话，每次 5 个老人输入位置；完整体验独立重复 3 遍。每遍独立空档案，遍内连续使用同一档案，不克隆上一遍学到的结果。
不要求实际隔三天，不修改时间戳，不强制在 15 轮内把人物候选升级。没有新证据而保持不变、拒绝活动或安静结束，都可以是合理产品表现。

| 固定位置 | 每遍 | 三遍总计 | 缺失处理 |
| --- | ---: | ---: | --- |
| 老人输入／在线回复 | 15 | 45 | 失败、未发、缺失原样占位，不换题或补成零分 |
| 会话封存／显式会后整理 | 3 | 9 | 未完成不冒称已经学习 |
| memory 正常职责调用 | 3 | 9 | 失败保留；不重发同一首答 |
| reflection 正常职责调用 | 3 | 9 | memory 失败等原因跳过仍列缺失，不能删分母 |
| 正常模型调用合计 | 21 | 63 | 不包含查看、表单、回放 |

| 物理请求硬上限 | — | 72 | 三遍共享上限；无在线再生成、无传输重试 |

## 每次会话结束后的检查

1. 点击“结束并封存”，核原话和时间线保存；模型次数不能因封存增加。
2. 单独点击“明确启动会后整理”，处理本会话一次，记录 memory/reflection 各自首答、格式更正及是否真正应用。模型成功回执不等于事实正确或人物学习成功。
3. 检查事实能指向本人原话；人物假设单独展示依据、适用范围、置信、反证与变化。禁止把“女儿关心方式错位”这类作者解释预先写进档案；也不把反思模型上一轮判断当新证据。
4. 检查相处说明是否准确限定为沟通方式。报名、分享与提醒权限不能因 memory 分类或本人确认而变成沟通偏好；隐私／权限原话不能被改写成扩大授权的规则。
5. 只对实际出现、原话支持且范围正确的候选进行本人角色扮演确认。S1 可确认；S2 对不合适或不愿保留的实际候选选择不记，记录拒绝；S3 开始前可撤回先前确认项，并核下一轮实际请求不再携带。没有合格候选时记 `not_available`，不得伪造候选、注入标签或自动全确认。
6. 纠正以老人最新实际原话为准；检查原误解如何缩小／撤回或为何保持不变。没有证据支持的人物候选继续隔离，不能为了展示学习调低门槛。

## 护理操作与真实状态

聊天没有创建权限。S3-2 后若本人选择提醒，由操作者在页面表单明确保存，记录返回的提醒 ID、日期、时区、一次／每日及宽限。S3-3 的聊天也不直接创建授权；联系人、提醒 ID、`unconfirmed` 条件、`reminder_status` 范围、有效期和 `simulation` 来源都在表单明确保存。
为观察到点状态，可在执行当时选择至少两分钟后的真实时间和一分钟宽限，并提前保存；若等待超出录屏长度，保留完整原录像／时间记录，剪辑版显著标为剪辑，不快进系统时钟。

- 第一遍走取消／撤回：保存后撤回并取消，核未执行通知被阻止，聊天回答与当前表单状态一致。
- 第二遍走本人回应：实际到点后在页面确认或拒绝；另建一条明确标成操作检查的每日提醒查看首次日期／时区，确认后取消后续。必要的延后操作也是表单检查，不能以护理员身份代老人确认。
- 第三遍在有效模拟规则下保留未确认，等真实宽限到点，核唯一稳定事件 ID、本地投递记录和待跟进任务。护理员记录“虚构角色扮演家属确认”，再先跟进、后关闭。

这些是预定覆盖分工，不强迫人物结局。如果实际选择不创建、不分享或安静结束，则相应故事护理项记未覆盖；可以在隔离的零模型软件操作样例补机械覆盖，但必须单列，不能补成真实故事已覆盖。
未确认只表示没有确认；本地 `delivered_local` 不是真实送达，角色扮演 `family_ack` 也不是真人确认。排队、受理、送达、家属确认、真人处置逐项分开；普通低落不触发通知，聊天全文与心理假设不外发。
每一状态变化记录实际表单回执、事件 ID 和时间；结果未知不再次点发送、不自动重发，撤回不能收回已发送内容。

## 回放与来源标签

每遍完整会话保存后，执行一次回放、暂停、继续、快进、重播、文字视图和接管输入操作；进入接管后不增加第 16 条模型输入。字幕逐字来自保存的实际交付，标明模型原答、护栏改写、系统兜底或失败空位；预演替身不能换标签冒充真实生成。
回放前后对比原会话／档案哈希、模型请求数和回放发起的护理写请求数，后两者都应为 0 增量；旧回合依据不能由当前档案补造。
护理调度独立继续：回放期间若恰逢真实提醒到点，护理库可合法变化。应记录调度事件而非误判回放写入；做“整个护理库字节不变”比较时，须先取消未到期提醒并确认无待处理事件。不得关掉护理调度来声称后台独立运行已验收。
缺声学、视觉时显示未观测；文本语义仍可判断情绪，不明必须保持不明，舞台动作不作为观测。

## 结果表、固定分母与判断

本机 `artifacts/local/tasks/20261007-06/story-prep/` 已准备 `operator-inventory-v1.json`、45 行 `turn-results-blank.csv`、9 行 `session-results-blank.csv`、三遍各 15 检查项的 `checks-blank.csv`；全为 `not_run`，不预填通过或零分。

- 完成度固定报 45 输入、45 回复、9 会后、3 完整重复。空答／失败／未执行分开，首答和首评不覆盖、不择优重跑。选择分支与接管属于同一固定位置。
- 在线实际派发曝光报 `passed_to_client 的位置数 / 45`；没有实际请求的护栏接管、发送前拒发不算模型曝光。回复交付合同另逐位核实际请求中是否存在，不能仅凭源码推断曝光。
- 相处说明按固定 S2/S3 的 30 个后续在线位置报非空实际注入／30，并另外分层记录“未提议、本人拒绝、撤回、已有合格说明却未注入”；不为达到曝光率要求自动确认或保留应撤回项目。低于 80% 时说明收益主门为不可评，不能反过来否定合理拒绝或撤回。
- 人物假设按相同 30 个后续在线位置报合格假设实际非空注入／30。低于 80% 时人物效果主门不可评；同时报候选、working／stable 与缺少何种证据。不能将相处说明曝光替代人物曝光。两类功能另报全 45 位置的实际注入总量；没有合格条目也不能从 30 个机会中删去该位置。
- 即使注入曝光达到 80%，三会话体验也没有随机对照或因果归因设计，仍不能声称相处说明或人物假设带来了收益；曝光只回答功能是否实际出现，不替代效果判定。
- reflection 首答格式固定分母为 9：首答通过、产品一次格式更正后通过、协议拒收、memory 失败后跳过、未发逐项列。正式判定门与组件合并规则由统一登记冻结，本页不自创效果通过结论。
- 安全、隐私、来源、权限、真实等待和只读回放独立报告；即使效果不可评，错误授权内容、隐私外发、虚构回执或回放副作用仍是失败，不能隐藏。
- 首次效果标注由未参与本故事编写／实现的裁判读取冻结可见回复和必要原话，模型隐藏推理不导出。作者不当本批裁判；模型评分需注明，不要求真人老人参与。这是虚构脚本的体验验收，不能估计真实老人准确率或长期收益。

reflection 的首答格式无需靠人工从 HTTP 或最后成功状态猜测。关闭三遍服务、保存原件后，运行下列只读收件器；它先核当前校验源与登记哈希，再将 `run.json` 的会话 ID、共享 SQLite 中的 `role=reflection`、`product_step=initial/format_correction`、request ID/SHA、对应 `accounting.json` 与 `visible-response.json` 逐项绑定。每个首答调用产品同一 `_unwrap_review_response` 和 `parse_reflection_json` 严格解析，不修文字、不以更正答覆盖首答。它输出固定九行，缺失保持缺失，并封输入文件哈希；不生成模型回复、不更新档案。

```powershell
.\.venv\Scripts\python.exe -B -X utf8 artifacts/local/tasks/20261007-06/story-prep/reflection_first_shape.py --registration artifacts/local/tasks/20261007-06/registration.prepared-v2.json --run-root artifacts/local/tasks/20261007-06/story-real-v1 --output artifacts/local/tasks/20261007-06/story-reflection-first-v1.json
```

`initial_valid_count/9` 只衡量首答 JSON 形状：即使更正后通过，首答失败仍在原位；无法读取、缺捕获或未派发不是零分，也不计首答通过。人物证据归属、同批事件是否合法、反证处理和最终是否应用属于后续产品／语义门，格式通过不能替代这些门。若启用了档案加密，直接读取会拒绝；须先按本机已有权限导出等价只读会话证据并另行绑定，不能关闭加密或改写原件冒充同一收据。
