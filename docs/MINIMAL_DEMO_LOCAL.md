# 本地使用

[当前进度](PROGRESS.md) · [产品与架构](PRODUCT.md) · [安全与隐私](../SECURITY.md)

本页说明本地 `release_deepseek_v1` 默认配置及保留的历史 `release_max_v1` 配置；实际整合、核验和发布状态只维护在 [PROGRESS](PROGRESS.md)。

## 安装和启动

需要 Python 3.10+，只用虚构内容。安装依赖可能联网，不执行模型。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\aria-web.exe --minimal --port 8081
```

Linux 使用对应虚拟环境路径：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/aria-web --minimal --port 8081
```

打开终端打印的本机地址。默认不读 `.env`，环境中有 Key 也不会启用模型、媒体或真实通知。
占位回复明确标记为本地预览，不能当成真实陪伴或人物学习。

## 五分钟现场演示

本场使用虚构的书展行程。请观众跟着陈师傅确认一条相处习惯，再决定愿意把哪句原话转达给谁。离线预览保存实际的页面操作和每轮输入快照，对话回复由本地占位客户端提供。

完成上面的安装后，在项目目录用 PowerShell 运行这一行。它只监听本机，每次启动都有新的演示资料目录。为第三幕使用的虚构档案，在终端输入两次自选的临时护理员密码（至少 12 个字符），然后打开终端打印的“最小体验入口”。三幕都在本人页面操作。

```powershell
.\.venv\Scripts\aria-web.exe --minimal --port 0 --care-setup-admin demo --minimal-data-dir (Join-Path $env:TEMP ("aria-demo-" + [guid]::NewGuid()))
```

### 第一幕 · 先由本人确认

点 **开始第一次会话**，输入“以后安排活动，先问问我。”，点 **发送这句话**。展开 **他说过希望怎样被对待**，此时没有生效的说明。点 **结束并封存**，再点 **本地规则提取相处说明**。把新卡片上的本人原话、待确认状态和规则来源指给观众看。

可以对观众说，“刚才我说的是自己的意愿。我先核对念念整理的意思，再决定要不要留下来。”点卡片上的 **按这句话记下**，看状态变为已确认。

### 第二幕 · 看同一条说明何时退出

点 **开始下一次会话**，发送“我们聊聊周末去书展的安排吧。”展开 **本轮实际输入依据**，打开 **本人确认的相处说明（实际选入内容）**，应有 1 条。在 **他说过希望怎样被对待** 中点 **撤回**，再发送“现在我想自己看看书展的日程。”同一栏应为 0 条。

展开上一轮对话的 **查看这一轮的输入依据 · 保存快照**，它仍显示 1 条。可以这样讲，“上一轮开始时，这条说明还有效。我撤回之后，新一轮就不再带上它。”这里展示的是本地输入选择。模型是否在后续对话里尊重这条意愿，需要用多会话实测判断。

### 第三幕 · 只分享自己挑的原话

保持第二次会话开启，发送“周六我想去书展。我还想自己挑一本诗集。”在 **我的提醒与通知授权** 中展开 **添加本地演示联系人**，称呼填“书友（虚构）”，点 **保存演示联系人**。

展开 **只转达我选定的一句话**，选择刚才的书展原话，在 **只保留要转达的原文** 中只留下“周六我想去书展。”，收件人选“书友（虚构）”。点 **核对这句话与收件人**。请观众读出屏幕上的收件人和完整内容，确认有关诗集的后半句没有带入。

勾选同意并点 **我批准这份完整预览**，先停在“已由本人批准 · 尚未发送”。请观众选择结局。点 **撤回这次转达**，卡片会变为“已撤回”。若希望演示送达，在批准状态另点 **发送到本地模拟收件箱**，查看“本地模拟接收”回执，消息只留在本机。最后点 **结束并封存**，在启动终端按 Ctrl+C 停止服务。

## 连续会话与会后整理

1. 开始会话，选填、修改或自由输入老人侧话语。点击发送只提交当前话语，不把未来台词、
   作者心理解释或尚未透露的背景提前交给 Agent。
2. 本版虚构多会话Demo每次十一轮；日常本地探索可自行决定轮数。“结束并封存”保存原话。下一会话继续同一虚构人物，实际时间不变造。
3. “明确启动会后整理”是单独操作。本地预览不运行模型；真实模式每次处理最早一个待整理
   会话。memory 整理事实，reflection 独立审核原会话、旧假设及证据。
   启动后后台处理封存快照，页面自动读取阶段状态，可开始下一会话、查看及撤回。
   同一调用台账仍串行发出物理请求；会后请求进行中可先输入，回执确定后再发送。
   旧结果提交时核对本人状态；不会覆盖新会话、恢复撤回说明或重写已删观察。
4. 侧栏区分事实、本人相处说明与人物假设，显示来源、范围、反证和纠正。候选未升格、
   无变化都正常；置信不是准确率。旧会话的普通档案侧栏标的是当前档案，不冒充过去时点快照。

事实和关系记录的主动引用必须有完整、可核查的本人来源轮；不能截去同轮保密限定后提起。
普通保密事实可保留为“只内化”，与认知隐私整轮排除不同。旧记录缺少完整来源时继续保留、
可供本人查看，但不会因旧“可引用”标记进入主动引用。

本人原话支持的相处说明先是待确认，确认后才进入后续在线输入；可选择不记或撤回。
撤回、取代后保留出处和变化记录，后续输入不再使用。相处说明不授予分享、提醒或通知权限。真实模式中，有合格语义审阅的待确认条目可点“让我听听这条复述”；主聊天展示本人原话和待确认整理，点“回答这条说明”后用自己的话回应。同次模型只提出确认/拒绝/以后再说/不明确，代码核本人、会话、当前轮、原问句与目标指纹；确认或拒绝须保存成功才显示。含纠正或新条件不确认原说明，可另表达后重新整理。邀请只对下一轮有效、5分钟过期，回放和旧会话不能操作；页面回执只证明展示，不证明阅读或模型语义准确。
默认预览中，“本地规则提议相处说明”是封存后的显式演示操作，不调用模型、不生成事实或
人物假设，也不完成会后整理队列；提议带规则来源。真实模式由手动或本人明确开启的自动会后 memory 调用提议，
仍需原话核验和本人确认；提取/确认的软件验证不能代替模型效果验证。

“本轮依据”保存当次真正进入请求的短上下文、相关事实、适用且有依据的人物假设、已确认
说明和有限护理状态。原会话出处不一定进入本轮输入，页面分开标记；不展示隐藏推理。
缺少旧快照时明确说明不可恢复，不用当前档案补造过去依据。回放读取原记录，不刷新依据。

会后整理默认手动。在侧栏“自动整理 · 由我选择”可明确开启后续新封存会话的自动整理，选择每日1至8次会话上限；每个任务可能有两次模型调用。不开启不自动调用，不回溯旧会话；重复封存、失败、未知费用和重启不自动重试。停止服务只封存，不新开模型任务。每日次数按固定时区在当前资料目录独立记录，清除体验不重置次数，费用台账仍保留。产品单次输出不合格会显示明确标注的系统
兜底回复，下一轮可以继续；它不算模型生成效果。保存结果不明或费用不明先停止后续调用。
仅下文规定的在线未收答失败可由本人确认保留费用后继续新输入；相同交互请求 ID 不再次执行，历史回放不会重新调用。

## 可选情绪读数与记忆变化记录

EM-1 允许接入方随当前文字请求显式提供 `external_emotion`，包含 `label`、`confidence`、
`modality`、`source` 四个字段。没有输入就不增加情绪提示；`unknown` 表示不明。
页面把读数标成“外部情绪读数，可能有误”，本人原话、拒绝和纠正优先；它不进入人物假设、
认知变化或医疗/通知升级证据。接口不会自行调用声学、视觉或情绪模型，也不声称观察到了声音或表情。
普通 Web 拒绝合成读数；专用 Python 实验能力对象绑定独立目录和虚构档案，实验结果显著标记。

“记忆与日常变化提醒”默认关闭。本人在页面开启后，手动整理或本人已开启的自动整理会抽取授权期间的本人
原话；普通聊天档案和人物反思不会把这些敏感记录当人物证据。本人可查看、逐条删除、关闭并选择
是否清除观察。校准和提醒规则只比较本人先前记录；不出病名、分数或诊断，不自动通知家人。
当前本地预览不调用会后模型，因此开启按钮不等于已抽取观察或证明功能有效。
真实v4同次返回可提出关闭观察，代码核对当前本人整句、轮次与来源；不凭词表关闭、
不允许模型开启或分享。关闭保留旧观察，删除仍由本人选择。未运行新语义题，不能据软件
检查声称理解所有撤回说法。文字页没有外部情绪读数时不自行提起变化；有合格趋势且不在冷却时，本人可选择“现在愿意聊这些记录”，页面填入专用话语，再点发送才调用模型。许可只用于紧接的当前会话一轮、5分钟有效；编辑话语、换轮、改同意或记录即失效。它不证明情绪平静，不改变校准/趋势/冷却，不授权分享。
详见 [C1 设计与边界](COGNITIVE_CHANGE.md)。

这里的“本人”是本机虚构人物 `fictional-chen` 的操作身份：持有体验凭证的人可代入该角色；
它不提供真实老人的身份核验。护理后台不能代本人开启或修改这些观察。不要输入真人健康资料。

## 舞台、字幕与回放

舞台动作只是表现；字幕来自实际交付回复，保留占位、真实生成或规则接管的来源。
支持暂停、文字视图、接管输入和保存回放；暂停不能取消已经提交的请求。本版不提供 TTS。
回放只读已取到的文字，不能重新调用模型、创建提醒或通知；动画不当感知证据。

旧截图和 60 秒预览来自本地占位流程，原件保留在本机，首发源码包不分发。
旧预览由 120 张截图按 2 fps 合成、经过剪辑、无音轨；不代表真实 Agent 效果或实时延迟。

## 护理员与模拟护理

首次在私有终端创建护理员并启动服务：

```powershell
.\.venv\Scripts\aria-web.exe --minimal --care-setup-admin caregiver --port 8081
```

按提示两次输入至少 12 字符密码；无默认密码。账号分配给虚构老人 `fictional-chen`，
已有账号不会被重置。以后省略设置参数，在 `/care` 登录；服务端检查负责老人范围。
Linux 对应命令为 `.venv/bin/aria-web --minimal --care-setup-admin caregiver --port 8081`。

- 在陪伴页或后台表单创建一次性/每日提醒，填日期、时间、时区和未确认宽限。
  只支持 `Asia/Shanghai`、`UTC`。聊天提要求不等于已创建，必须明确保存并核查状态。
- 老人可以确认收到、拒绝、延后或取消；服务端拒绝护理员代老人确认、拒绝或延后。
  护理员仍可在负责范围内管理提醒和记录跟进。超时只是“未确认”，
  不能推断没吃药或遇险。
- 到点先生成“尚未展示”记录；打开的页面定时读取新提醒。只有本人页面当前可见、展开且
  提醒卡进入视窗后，才回报本期展示，并从服务端时间启动宽限。回放、历史查看、隐藏页面
  不回报展示。展示回执不证明本人已读、回应或完成活动；无回执不会升级成未确认通知。
  延后到点须新一期展示；旧版缺展示证据的期次保留历史，不能继承送达或宽限资格。
- 添加虚构联系人，指定提醒、未确认触发、仅提醒状态的分享范围和有效期，可撤回。
  这是模拟授权，不含真实收件地址；聊天全文与人物假设不外发。
- 有效规则满足时自动记入本地通知台账，无须每条再批。区分排队、受理、送达、家属确认
  和人工跟进；模拟记录不等于真人收到。跟进任务记录处置后关闭。
- 撤回、取消或老人回应阻止尚未执行的通知；结果未知不自动重发。已发送内容不能收回。

护理相关回合读取本人最近有限记录，最多三条提醒及相应有限期次、授权、通知与跟进状态。
遗漏数量和读取失败可见；失败不当作没有记录。快照不含姓名/地址、通知正文、跟进备注或
登录资料，真实模型模式会将该快照随本轮输入发送。每轮保存当时依据，回放不刷新旧快照。
这是关键词触发的有限只读参考，不赋予聊天写操作能力，也不是新人物证据或成功回执。

护理调度在服务运行时独立继续，包括关闭聊天或回放时；停止服务后暂停。错过的每日提醒
不会补记为送达。首发仅模拟通知，CLI 没有真实外发开关。

## 本人选择具体内容的本地转达

先按上节创建护理演示账号，在本人页“我的提醒与通知授权”添加虚构本地联系人。
在当前活动会话发送并保存一句话后，展开“只转达我选定的一句话”：

1. 选择已保存的本人原话，可在“只保留要转达的原文”中删去开头或结尾，仅保留一个连续片段；不能添加或改写。未删减时使用整段原话。再选择本人本地联系人，点击“核对这句话与收件人”。
2. 核对完整的所选片段、收件人及本地模拟通道，勾选批准，再点“我批准这份完整预览”。预览、批准和发送都绑定原会话、原句及原文范围，未选文字不随本次转达发送。
3. 此时仍未发送；另点“发送到本地模拟收件箱”才作一次本地尝试，并显示独立回执。

五分钟内的批准只对应这份预览。内容、收件人、会话或服务状态变化后不能沿用。
护理员不能代选、代批或代发；历史和回放只读。不会自动选择人物假设、变化记录或
聊天摘录，也不把转达记录写入模型输入。提醒状态授权与本次具体内容批准分别保存。
刷新不重发；结果未知只可读取或撤回，不换编号再发。未开始的草稿可撤回，
尝试已经开始后撤回不能保证内容未被接收。本地回执不代表真实家属收到或阅读。
转达库读取失败会停止转达并标记未知，普通聊天仍可继续；不沿用旧来源或联系人缓存。

## 数据、删除与失败

默认根目录 `data/minimal_demo`，可用 `--minimal-data-dir` 指定独立根目录。预览与真实模式
分别在 `local_preview`、`live`，不要指向真实老人资料。只支持单服务实例。

“清除本次体验资料”删除当前模式的对话、档案、队列和本虚构老人的护理记录，保留护理
账号/分配与真实模式调用台账；同时清除本体验转达正文，未知尝试仍保留不含正文的防重发身份。
Max候选还清除当前体验的模型公开首答正文、首段可见文本及流式公开帧，并以持久擦除记录阻止旧在途返回重新写回内容。
只保留核账、防重发与来源核验所需的最小身份、金额、状态和非正文摘要；费用、失败状态及未知预留不重置。
擦除失败不会报告成功。此操作不清其他模式、备份或云端已接收的数据，也不能撤回已经发生的发送。
`ARIA_PROFILE_KEY` 配合 `secure` 依赖可加密档案及回放，**不加密护理库、转达库与调用台账**。
原话整理队列每会话最多 120 轮/60,000 字符、保留 24 小时；完整回放保留至主动清除。
记录的“可引用”字段只接受真正的布尔值，字符串 `"false"` 不会变成允许引用。
旧档案含非法类型时明确读取失败并保留原文件待修复，不会静默删除资料或重建空档案。

## 显式启用文字模型

当前普通Web入口和 `scripts/run_story.py` / `scripts/run_safety_set.py` 默认选择 `release_deepseek_v1`。在线、安全复核和偏好确认使用 `deepseek/deepseek-v4.1-flash-1017`，固定Together端点；三者推理明确关闭，输出上限分别为4096、1024、60。会后路由须单独选择：本项目当前评测明确使用同一DeepSeek/Together；不指定时仍是历史Sonnet选项。默认仍为零模型本地预览，设置Key不启动调用。

为当前全DeepSeek配置保存公开models及DeepSeek端点元数据，在线/会后使用同一组原件；使用新策略、输出及资料目录，原费用和未知预留仍计入总预算，不能因换目录重新起算：

```powershell
.\.venv\Scripts\aria-model-policy.exe --release-profile release_deepseek_v1 --offline-model deepseek/deepseek-v4.1-flash-1017 --offline-provider together --cover-all-price-tiers --models-json artifacts/local/model-metadata/models.json --online-endpoints-json artifacts/local/model-metadata/deepseek-endpoints.json --offline-endpoints-json artifacts/local/model-metadata/deepseek-endpoints.json --output artifacts/local/deepseek-model-policy.json
```

### 完整格式失败的隔离（普通入口 v6 软件修复）

对于已经收到完整响应、费用已核定的特定格式失败，系统核对本次请求、失败轮次和持久状态。若只新增合法保护提示及安全审计，且没有事实、偏好、权限或其他业务半提交，保留原失败和已显示保护提示，拒绝展示坏的模型正文，再开放下一次输入。此路径无需点击恢复，但不会自动发送任何新请求，也不重试原请求。未知费用/无完整答复仍走上面的本人明确确认路径；两者均不释放旧预留。

该修复独核为99个实际执行检查通过，覆盖37个唯一检查位置（含两个隔离安装环境）；不是99个模型案例。它解决失败后的阻塞，不修正模型原答，不改变严重安全停批、评分门槛或语义结论。普通v6没有一轮完整的新真实模型验收；旧格式失败、偏好确认失败、人物曝光不足、整轮会后记忆排除及本次严重安全失败仍为已知限制。
