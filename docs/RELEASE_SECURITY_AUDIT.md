# 发布树安全与隐私审查

当前状态、版本和本轮证据统一见 [PROGRESS](PROGRESS.md)。本页说明 R3 的检查范围、
可复跑方法和已知限制；不是运行时渗透测试，也不是公开发布批准。

## 检查方法

先由 `scripts/build_minimal_release.py --output` 构建明确白名单的 ZIP，再运行
`--verify` 复算每份源码摘要。R3 只扫描这个已验证的发布树，包括生成的完整性清单，
不读取真实环境配置、运行资料、Git 历史或私人归档。

密钥扫描使用隔离工具环境中的 `detect-secrets==1.5.0`，以 `--all-files --no-verify`
扫描解包目录。`--no-verify` 禁止为验证疑似凭据而请求外部服务；扫描阶段没有账号 API
调用。这个工具环境与项目执行模型时的依赖环境分开，不改变已冻结的运行依赖。

附加正则检查 Windows/macOS/Linux 用户路径、本机用户名、邮箱、手机号、长数字账号
和账号赋值。报告只写相对路径、行号、类别和绑定原行的摘要 ID，不输出命中值、源码行
或密钥摘要。正则有误报，也不能证明检测到了所有种类的个人信息。

每项人工解释绑定精确文件、行号、类别和当时字节；文本变化不能沿用旧解释。解释文件
中多余的旧条目也会使检查要求复核。生成的 `RELEASE_MANIFEST.json` 中 SHA-256 例外
由程序复算对应文件后逐项标记，不能把任意源码中名为 hash 的字段自动豁免。

在独立工具环境安装上述固定版本后，可运行：

```powershell
python scripts/build_minimal_release.py --output dist/candidate-source.zip
python scripts/build_minimal_release.py --verify dist/candidate-source.zip
python scripts/audit_release.py dist/candidate-source.zip --output audit-first.json
python scripts/audit_release.py dist/candidate-source.zip --reviews reviewed-findings.json --output audit-reviewed.json
```

第二个扫描命令须在逐项核对第一份报告后执行。`reviewed-findings.json` 的结构是
`schema: aria_release_review_v1` 和 `reviews` 数组；每项只含 `id`、`category`、`reason`。
工具不会自动将所有测试或文档命中视为安全；报告为 `review_required` 时仍有工作。
已有输出不能覆盖。原始发布 ZIP、完整脱敏报告和对应解释文件由任务归档保留。

## 本轮解释口径

| 命中 | 保留理由 | 边界 |
| --- | --- | --- |
| 发布清单、冻结合同、公开端点快照中的完整性摘要 | 用于绑定公开源码、请求或公开元数据；不是访问凭据 | 每项按所在文件与字段核对，不将所有高熵字符串一概排除 |
| 合成测试中的请求编号、固定随机种子、密码/私钥标记 | 用于验证脱敏、错误处理和密钥扫描拒绝行为 | 不构成默认密码；只解释本次具体命中位置 |
| 虚构脚本实验的本地请求或会话编号 | 续接工具逐项绑定已封存检查点，使用 `fictional_experiment_identifier` 单独解释 | 编号不是原话、私人身份或访问凭据；不得将真实私人会话编号套用此类别 |
| 审计测试中的示例路径、邮箱、手机号、账号 | 审计器自身的虚构检测夹具 | 不是真人联系资料，不能拿这些通过数冒充实际资料审查 |
| 进度与发布清单中的目标 GitHub 账号 | 用户明确指定的目标账号，保留发布授权上下文 | 不扩大成账号 API、建仓库或推送授权 |
| LICENSE 与项目元数据中的版权姓名 | 用户明确批准的公开署名 | 不删除合法署名，不推广到其他私人身份资料 |
| 第三方许可与上游来源 | 保留适用版权与来源信息，见 [第三方说明](../THIRD_PARTY_NOTICES.md) | 不把上游公开资料算作本机私人信息 |

## 媒体与命名残留

发布策略 `aria-minimal-source-6` 排除全部 `docs/media`，sdist 清单同步排除。旧占位 PNG/MP4
原件仍在本机；没有删除或重新解释旧验证结果。版本 2、3 的 ZIP 仍能用各自原策略和原范围说明
验证，并明确返回 `legacy_media_included`，不能据此宣称旧包也满足新版无媒体要求。
新报告只接受当前版本 6。版本 4 加入 EM-1、C1、E1b/C-test/E3 准备源码和必要合成夹具；
版本 5 加入 E1b 执行、形成审核、二次裁判及有界续接工具。版本 6 仅额外点名纳入 E1b-R
执行、资格核验、评分、保留已收首答的续接工具及对应合同；本轮新增产品模块与测试仍遵循原有源码目录规则。
不包含 PrefEval 原数据、模板、私人 campaign、实际模型回复、授权原件或费用账本，包含
执行工具也不授予付费权限。任务 `20261004-05` 的版本 5 包及其他旧包继续按原范围验证，不能当作
当前源码的审查回执。将来加入截图或视频前，须单独审查画面中的个人资料和凭据。

下列命名保留供产品改名时判断；新版产品源码和旧实验封印分别保留：

| 残留名称 | 当前实际职责 | 是否意味着旧能力仍开启 |
| --- | --- | --- |
| `aria/voice/minimal.py`、`aria/voice/web.py`、`aria/voice/__init__.py` | 本地文字 Web 装配与 HTTP 服务 | 否；目录名沿用历史，不能据此声称具备语音识别或 TTS |
| `aria/assets/voice/minimal.html`、`care.html`、`README.md` | 对话舞台与护理后台静态页面 | 否；是页面资产目录 |
| Python 包名 `aria`、命令 `aria-web` | 当前模块导入与启动接口 | 名称调整另版处理，不能仅改目录导致导入失效 |
| `aria/bench` 的 E1/E2 文件 | 保留的小型实验与停止状态复验 | 不恢复旧大型实验平台，不随包加入下载数据或私有实验输出 |

## 未覆盖与后续

没有审计旧 Git 历史；公开仓库应按发布流程使用干净历史，不能直接推送当前工作区。
联网冷安装、三遍浏览器故事和截图检查是否完成，以对应版本的实际回执为准；CI 配置、
本机依赖复用或旧包扫描不能替代这些验收。未做真人资料审计、专业医学全面审核或真实
通知验收。最终公开前在 R1、R8 和口径修改后的最终 ZIP 上重新扫描。

原知识库的通用漏服降压药表述已在新版生产源码中收窄：依具体药物、剂量和时间核对
说明书，或咨询医生/药师，不统一建议补服或跳过。修订参考
[NHS SPS 的漏服/延后服药指导](https://sps.nhs.uk/articles/advising-on-missed-or-delayed-doses-of-medicines/)
（2026-10-01 查阅）；旧实验字节仍由原冻结快照保存。这解决一处已发现的泛化表达，
不代表已完成整个知识库的专业医学验收。
