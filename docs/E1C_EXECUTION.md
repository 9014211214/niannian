# E1c 工程接口与执行边界

进度只维护于 [PROGRESS](PROGRESS.md)。研究依据为 [VALIDATION](VALIDATION.md) 中的独立作者留出集方案。

E1c 的结构、首稿保存、多来源对照清理和软件 runner 已接入工程。正式作者尚未出题，未运行真实模型、评分或形成门。E1c 排在 E1b 收尾之后；本地软件验证不会授权费用，也不把 E1b 的旧首答算作 E1c 留出答复。

## 题库与首稿

`aria.bench.e1c_cases` 使用独立的 `e1c_format_v1` JSON 合同：12 题、六类各两题，ID `e1c_a1` 到 `e1c_f2`；S1/S2 各 12 轮，S3 为 7 轮铺垫、1 轮观察位、2 轮跟进。E1b 的 18 题 loader 和原题库不改。

每题的 `preference_sources` 是完整原话及其 `{session, turn, quote}`，可来自同一输入、同会话多轮或两个会话；只允许已披露的 S1/S2，位置必须唯一、按时间排序且逐字相符。它不要求命中特定 R1 句式，也不检查模型能否提取。人物背景、作者标注、预期偏好、评分规则和未来轮次不进入本轮模型输入。

`aria.bench.e1c_source.seal_first_submission` 先独占目录并保存原稿原字节，再保存作者声明的 JSON 表示，最后验证来源和结构。格式或来源声明不合格也占用首次提交，保存失败回执；没有“替换为更容易通过的题”接口。文件保存失败会报错，不用成功回执覆盖失败。软件夹具明确标记 `software_fixture_only`，默认 loader 拒绝把它当正式题库。

来源合同保留独立作者身份、首次 brief SHA、唯一提供材料清单和不按结果筛题的声明。声明不能证明作者不可见的既往知识；正式作者必须在 E1b 汇总后用不继承项目上下文的独立任务，只提供范围、六类和格式，不提供产品提示、R1 规则、E1b 题目或答复。

`load_first_submission` 由外部给定首稿 receipt SHA，重新核验 receipt、原稿与作者声明的精确字节、题序、来源类型和逐项 ID；拒绝链接/reparse 路径。后续 runner 每开始一题都重新读原件，不信已缓存题库。原稿不按产品输出、提取成功率或评分删题、换题、调序。

## 多来源 A0 与实际产品路径

`aria.bench.e1c_runner.E1cRunner` 复用真实的在线、memory、reflection、本人确认与分支保存路径。两会话后，把作者来源坐标映射到实际 session ID；A0 清空全部显式相处说明，并逐来源清除关联的事实、人物假设、关系记录。混合来源结论整条移除；A1 与共享原件不变。每个来源的删除 ID 单独留痕，不改时间戳、不重写历史审计。

E1b 仅增加可覆盖的报告版本、情绪计划、A0 清理和报告元数据钩子；默认仍按第二会话的单个 `pref_turn` 清理。E1c 报告和合成情绪来源使用自己的标识。底层 memory/reflection 捕获 Schema 及会话操作 ID 继续复用原组件，并在 E1c 报告中明确记录，不能据此把 E1c 归为旧 E1b 活动。

三会话流程每题 84 次 online、2 次 memory、2 次 reflection，第三会话两臂各三次重复；只评每次重复的末三轮。完整 12 题库存为 1008 online＋24 memory＋24 reflection＝1056 基本位置，回复评分分母 216、形成分母 12。`planned_positions(suite, seed=...)` 的顺序按实际 runner 的平衡臂顺序生成；合成情绪按同一固定 seed 生成，两臂和重复使用同一读数。

当前 runner 必须使用已封存的软件夹具、具名本地客户端和隔离的 `E1cExperimentApp`。它拒绝预筛、跳题、重复题、外部护理与真实模型配置；即使传入旧 E1b 的 `allow_model_calls=True` 也不会开启 E1c 消费。正式题不能被拿来软件预演后调 R1。

## 费用准备与尚未放行的部分

`aria.bench.e1c_registration` 提供库存、历史费用的 Decimal 算术和预算情景函数。历史已知费用、每笔未知的活动 ID、原请求 ID、请求 SHA/正数预留、旧账本与结论 SHA 一并保留；按活动与原请求 ID 组合去重，不拼接或改写原 ID，不以新的空账本清零。不同活动可能使用相同原请求 ID，仍须保留两笔；同活动同 ID 换 SHA 不能伪装成另一笔。只接受“E1b 已结账”的准备输入，但这仍是输入声明，正式登记必须再实际核验所指账本和汇总原件。

`estimate_e1c_budget` 必须显式传入三个角色的模型、价格元数据 SHA、输入/输出 token 上界与单价，不联网、不内置过时价格。默认情景不加重发；若计算一次 reflection 格式更正、每逻辑位置共享两次基础设施重发，则是 1056＋24＋2112＝3192 次物理上界。初始和格式更正共享重发池，不能展开为两份重发额度。费用输出含历史承诺金额，始终 `execution_authorized=false`；裁判未纳入时明确说明，不能称为完整真实预算或费用批准。

正式调用还必须在 E1b 收尾后完成：

1. 独立作者首次交题、完整来源封印和产品/提示/模型版本登记；不从 E1b 继承任何实验首答。
2. E1c 专用执行入口、费用授权与守卫，实际核验历史已知费用、九笔旧未知及保守预留，明确新未知/更正/重发额度和累计停报线。接受旧未知不等于无限费用，E3 预算不挪用。
3. 1056 位置的完整资格核对、216 首次盲评及跨会话形成包。既有 E1b qualification/formation 仍绑定旧题库和单来源，不能直接把 E1c 报告送入旧入口称为可评。
4. 明确裁判方案并计入真实完整预算，另版冻结后才实发；判断仍用预先登记的主门和形成门，不为通过调题或放宽规则。

软件测试覆盖结构反例、首稿不可替换、跨会话 A0、旧 E1b 单来源不变、拒付费，以及一题 88 次本地替身的实际产品流程。它们不证明自然偏好能被提取，也不证明真实老人长期陪伴效果。
