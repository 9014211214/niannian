# Aria

[English](README.md) · [当前进度](docs/PROGRESS.md)

Aria 是一个本地老人陪伴原型：理解他希望被怎样对待，保留理解的依据，允许他纠正，
并在回应和行动时尊重他的选择。陪伴、人物理解与小型本地护理流程在同一个 Web 中衔接。
**真实模型效果尚未通过验收**，已有安全误报和任务回应不完整的实例。通知仅为模拟，
本原型不是可直接投入使用的护理服务。详见[证据边界](docs/EVIDENCE.md)。

三项设计贯穿这个原型：

- 事实、本人确认的相处说明和推断的人物假设分开。
- 保留出处、适用范围、纠正和反证；DISC、Big Five、依恋等用于沟通，不是诊断或永久标签。
- 行动须有真实能力、许可和回执；聊天、相处说明或模型风险标签不能产生护理授权。

## 可以体验什么

使用虚构人物探索本地流程。下表说明已实现的功能，不代表真实使用效果已通过。

| 体验 | 本地已有 | 尚未证明或有限制的部分 |
| --- | --- | --- |
| 对话 | 字幕、可编辑输入、保存回放、可选真实文字模型 | 冻结版本的任务与回复检查曾失败；默认回复是占位内容。 |
| 事实与相处说明 | 查看来源、纠正、本人确认和撤回；显式启动会后整理 | 修补后已观察到说明进入请求，但收益与稳定质量仍未证明。 |
| 人物假设 | 可修订候选、证据和范围，达到组合门后才使用 | 此前E1c-v2与三会话检查未测到实际注入及收益；长期形成和收益未验证。 |
| 安全 | 关键词兜底与同次在线模型风险标注 | 已有误报替换普通回复；广泛说法的风险识别未通过专项验收。 |
| 护理 | 护理员范围、提醒、可撤回授权、回执状态及跟进 | 通知通道为本地模拟，不能证明真实家属收到或护理效果。 |
| 日常变化记录 | 默认关闭；本人可开启、查看原话、删除或关闭 | 不作诊断，专项真实模型效果检查尚未完成。 |

## 启动

需要 Python 3.10 或更新版本。在项目目录执行，Windows：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\aria-web.exe --minimal --port 8081
```

Linux：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/aria-web --minimal --port 8081
```

打开终端显示的本机地址。默认使用有明确标记的占位回复，不读 `.env`，不调用模型，
不发送真实通知。只输入虚构内容；安装依赖可能需要联网。

需要护理后台时，在启动命令后增加 `--care-setup-admin caregiver`，在私有终端提示中
设置密码。没有默认密码，也不要把密码写进命令或聊天。

真实文字模型模式还须同时提供 `--enable-model-calls`、`--model-max-requests`、
`--model-stop-cost-usd` 和 **`--model-reservation-policy`**。先用
`scripts/prepare_model_policy.py` 从已保存的公开模型/端点资料离线生成价格预留策略，
具体文件与命令见[本地指南](docs/MINIMAL_DEMO_LOCAL.md#显式启用文字模型)。有 Key 或策略文件
不会自动启用模型。发送前预留费用，结果未知即停发；它不是供应商账单保证。

## 模型模式与边界

最小入口的真实在线调用采用 `v3` 协议和 `mode_v1` 四档表达；同一次调用给出安全风险标注，
简单聊天也经过该流程。旧 `v1/v2` 实验保留原协议，`profile_v1` 画像仍是显式实验。
关键词底线保留；语义标注不能授权通知或修改医疗规则。软件检查、真实模型检查和效果验收
属于各自受测版本，后续修补和隔离候选不继承旧模型结论。会后整理默认手动；本人可明确开启后续新封存会话的自动整理，受每日任务数及原费用边界控制。已审阅的相处说明可先在本人页面复述，再用对话回答确认；合格变化记录可由本人选择接下来一次请求聊聊，不伪造情绪读数。这些是本地工程路径，模型理解和实际时机效果仍未验收。
本人可在当前活动会话中选择一整句已保存原话，核对收件人与本地通道，先批准、再另点发送到独立模拟收件箱。预览五分钟有效，刷新不重发，结果未知停止后续转达；真实外发与真实 Agent 短片仍未完成。

首发通知使用接口与模拟通道。摄像头、声学情绪、ASR/TTS、Omni、全双工、硬件、
其他产品场景和旧大型研究平台不在本版本中。本原型不是可直接投入机构使用的护理系统。
外部情绪接口不会启动传感器或情绪模型；合成读数只能在独立 Python 实验目录中使用并显著标记。
当轮外部读数可能有误；缺失不加情绪提示，不明不当作平静。每轮保留实际输入依据。
本机体验凭证的持有人可以代表虚构本人操作，这不是实际老人的身份核验；护理员权限不代替本人操作。

原有负结果按版本保留：

- [E1b-R](docs/E1BR_RESULTS_2026_10_05.md)：14个相处说明候选全部在确认前拒收，未测到原定使用效果。
- [E1c-v2](docs/E1CV2_RESULTS_2026_10_07.md)及[后续验证](docs/VALIDATION_RESULTS_2026_10_07.md)：
  效果门失败或不可评。旧三会话未测到人物假设注入，不能据此推定形成所需的固定会话数。
- [24题双臂检查](docs/VALIDATION_RESULTS_2026_10_07.md#8-2026-10-08-另版双臂检查)：收到30份回复，
  1次限流，17个位置未发。收到的回复均符合输出Schema；低曝光使两效果主门不可评，
  独立保护门和固定分母格式门失败。1.8提示与reflection格式候选仍隔离，未合入产品。
- [证据与早期研究](docs/EVIDENCE.md)：不完整运行及旧E1改善/延迟门失败保留；
  CPED停在本机准备，没有真实E2。人工抽样校准是可选项，运行和开发原型无需招募老人。

当前修补与新的隔离候选只在进度入口跟踪。软件测试和模拟流程不能证明真实老人获益。
